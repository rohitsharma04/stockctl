# India/NSE alternatives to a custom `stockctl`

> Research date: 2026-07-26. Capability statements below are limited to vendor/exchange documentation and inspected open-source project material. Exchange website pages were intermittently inaccessible from this environment; links are retained as primary references.

## Decision in one line

Use **official NSE reports and corporate-filings pages as the source of record**, persist a versioned local warehouse, and use **one broker API only for authenticated tradable-universe snapshots, current/streaming data, and optional order automation**. Of the three, **Kite Connect is the clearest documented all-in-one data-and-automation interface**; **Upstox is a strong alternative where its Analytics Token/static-IP model fits**; **FYERS is viable for broker automation but should not be treated as a corporate-actions/master-data system**. No inspected open-source project is a replacement for licensed/official NSE history or corporate-action data.

## Broker/platform findings

### Zerodha Kite Connect — recommended broker interface if its account/pricing model is acceptable

- **EOD/history:** `GET /instruments/historical/:instrument_token/:interval`; vendor says archived candles span back several years and include timestamp/OHLC/volume/OI. Intervals include daily and minute through 60-minute. Continuous futures and OI flags are documented.
- **Current data & universe:** quote/OHLC/LTP APIs plus WebSocket. `/instruments` provides a gzipped CSV across exchanges and is generated daily; Zerodha explicitly says its `last_price` is not real time and recommends requesting it once daily (about 08:30) and storing it locally. Use `exchange + tradingsymbol`, not numeric instrument token, as the durable key because derivative tokens may be reused after expiry.
- **Automation:** REST orders/GTT/portfolio plus webhooks/postbacks. Published rate limits: quote 1 request/sec, historical candles 3/sec, orders 10/sec, other endpoints 10/sec. A 403 session error requires re-login; implement idempotency and an order state reconciler.
- **Important gap:** no documented corporate-action or historical index-constituent API. Preserve NSE notices and your daily master snapshots separately.
- **Cost/terms:** the official docs reviewed establish that a trading account, TOTP/2FA and developer app/login flow are prerequisites, but did **not** publish a tariff in the pages accessed. Check the authenticated Kite developer portal/contract before budget approval rather than relying on third-party “API fee” articles.
- Sources: [overview](https://kite.trade/docs/connect/v3/), [history](https://kite.trade/docs/connect/v3/historical/), [quotes/instruments](https://kite.trade/docs/connect/v3/market-quotes/), [rate limits/errors](https://kite.trade/docs/connect/v3/exceptions/#api-rate-limit).

### Upstox Developer API — good alternative, especially for a read-heavy analytic client

- **Capabilities explicitly listed by the API hub:** historical candles, market quotes, expired instruments, option chain, market information, fundamentals and news; live WebSocket market data and portfolio updates; and webhooks for order/GTT notifications. It also supports place/modify/cancel/exit/GTT order operations and a sandbox limited to place/modify/cancel.
- **Token/automation constraint:** normal access tokens must be regenerated daily. Upstox says its Analytics Token is generated once and supports market-data/realtime APIs; portfolio/account read-only access with it also requires a registered static IP. This makes it potentially attractive for a fixed-IP data collector, but is a deployment constraint.
- **Corporate actions:** not a documented capability in the reviewed hub. “Fundamentals” is not evidence of complete corporate-action, ex-date, or historical price-adjustment coverage.
- **Cost/terms:** no API price was published in the reachable documentation pages. The hub prominently flags live regulatory changes for API/algo trading; check current announcements, user agreement and app dashboard terms before deploying unattended orders.
- Sources: [API hub](https://upstox.com/developer/api-documentation/), [app management](https://account.upstox.com/developer/apps), [regulatory announcement link exposed by hub](https://upstox.com/developer/api-documentation/).

### FYERS API v3 — viable execution/data adapter; do not rely on it as master data

- **Capabilities explicitly documented:** REST-like APIs for fresh/multiple real-time orders, modify/cancel, orderbook/tradebook/positions/holdings/funds; Data API, WebSocket, order WebSocket, tick-by-tick WebSocket, postbacks and price alerts. Official Python, Node, Web JS, C#, Java, Go and C libraries are linked.
- **Constraints:** OAuth-style app/login flow and `api_id:access_token` Authorization header are documented. The portal includes an April 2026 regulatory-changes section, so automated-order behavior must be revalidated against current broker requirements.
- **Data/corporate actions:** the docs reviewed do not state a historical-retention policy, adjusted-price policy, corporate-actions feed, or point-in-time universe service. Treat FYERS data as a broker feed and independently archive/validate it for research.
- **Cost/terms:** no API tariff was published in the documentation inspected; use the broker’s current app/account agreement as the decision source.
- Sources: [FYERS API v3 docs](https://myapi.fyers.in/docsv3), [FYERS Python SDK](https://github.com/FyersDev/fyers-api-sample-code). The docs navigation contains the current “Regulatory Changes (April 2026)” section; consult it in the live documentation.

## Official NSE data: the trust anchor

- **EOD:** use the official [NSE EOD/Historical Data subscription page](https://www.nseindia.com/static/market-data/eod-historical-data-subscription) and [NSE All Reports](https://www.nseindia.com/all-reports), including daily Bhavcopy/report archives. Download immutable raw files with retrieval timestamp and SHA-256; normalize from the raw file rather than overwriting it.
- **Corporate actions & filings:** NSE's live official endpoints are [corporate actions](https://www.nseindia.com/api/corporates-corporateActions?index=equities) and [corporate announcements](https://www.nseindia.com/api/corporate-announcements?index=equities&page=1&perPage=10); its [corporate-data subscription page](https://www.nseindia.com/static/market-data/corporate-data-subscription) is the licensing/product starting point. Capture the announcement/action identifier, symbol/ISIN, declared, ex/record/payment dates, action ratio/type, and the source document URL. Reconcile against the issuer filing when an adjustment matters.
- **Universes:** distinguish (1) exchange-listed/tradable symbols, (2) broker tradability, and (3) index membership. Get index constituent methodology/files from [NSE Indices](https://www.niftyindices.com/) and retain dated snapshots; do not create a historical backtest universe by using today’s list.
- **Licensing boundary:** official website availability does not itself grant bulk redistribution or commercial real-time use. For product/redistribution/low-latency needs, start with NSE's [EOD/historical-data](https://www.nseindia.com/static/market-data/eod-historical-data-subscription) and [corporate-data](https://www.nseindia.com/static/market-data/corporate-data-subscription) product pages and obtain the applicable data agreement rather than treating browser endpoints as an unrestricted API.

## Open-source: useful layers, not authoritative data vendors

1. **[OpenAlgo](https://github.com/marketcalls/openalgo)** — the strongest current self-hosted India broker-abstraction candidate found. Public Apache-2.0 project, actively maintained when inspected (recent commits), with broker adapters, REST API, event/order-update work, data/download areas, sandbox, strategy-management material and API/MCP-related directories. It can reduce the custom execution surface and support multiple brokers. **Use it only above a separately governed data store**; validate the adapter for your selected broker and current SEBI/broker algo rules before live trading.
2. **[AlgoBulls PyAlgoTrading](https://github.com/algobulls/pyalgotrading)** — MIT-licensed official Python package. Its README states that one strategy codebase can backtest, paper trade and real trade, and it supplies notebooks for NSE as well as NASDAQ. This is a reasonable research/prototyping candidate, but it is platform-coupled and is not a corporate-action or NSE-data authority. The inspected main-branch commit was about five months old.
3. **Screening conclusion:** no inspected open-source India/NSE screener demonstrated documented, authoritative coverage of prices, actions, fundamentals, historical index membership and data licensing. Build screening against the local NSE-first warehouse (for example with DuckDB/Parquet + Python/SQL/vectorbt/backtrader), or use a commercial/licensed data provider after validating adjustment and redistribution rights. Do not make an unofficial scraper the root of a production screener.

## Recommended replacement architecture

1. **NSE ingestion job (daily):** collect EOD/report files, corporate actions/filings and dated universe/index snapshots; save raw artifacts and parsed tables. Run validation (row counts, ISIN/symbol matching, duplicate actions, missing sessions).
2. **Research/screener:** query the local point-in-time warehouse. Adjust historical prices only through a versioned action pipeline and retain both raw and adjusted series. This is the only way to make universe and corporate-action assumptions auditable.
3. **Market data adapter:** select Kite if you want the most explicit historical/quote/instrument docs and known rate limits; select Upstox if its Analytics Token/static-IP design is operationally preferable; select FYERS if its order/data websocket capabilities fit an existing FYERS account. Cache broker instrument snapshots independently.
4. **Optional execution:** put OpenAlgo (or a thin internal adapter) behind a kill switch, position/order limits, idempotent client order IDs, WebSocket/postback reconciliation, audit logging and human approval for initial rollout. Broker APIs do not remove Indian regulatory, exchange, broker, account, or data-licensing obligations.

## Bottom-line recommendation

For a trustworthy replacement, **do not replace `stockctl` with a broker API alone**. Keep/construct the NSE-first warehouse and use **Kite Connect as the default broker adapter** if the commercial/account terms are acceptable; it has the most specific evidence here for multi-year candles, real-time quote snapshots, daily instrument files, streaming and rate limits. **Upstox is the best alternate** where its Analytics Token/static-IP model helps a read-heavy collector. **FYERS is a reasonable execution adapter**, but needs more direct verification for historical-data scope. Use **OpenAlgo only as a self-hosted integration/orchestration layer**, never as the source of record.
